# 정치자금 식당(맛집) 기능 설계

> 상태: 승인 대기 (브레인스토밍 산출물)
> 날짜: 2026-06-16
> 사이트: 의정감시 (asm.zihado.com) · Nuxt 4 / Cloudflare Workers

## 1. 목표

국회의원 **정치자금 지출내역**에서 "식당 지출"만 추려, 정치인이 어디서 먹는지(=pick한 식당)를
보여주고, 펀팩트로 다양한 축(당·나이·성별·띠·재산·아파트 평수·지역구)별로 분석한다.

사용자 요구 요약:
1. 정치인이 pick한 식당을 볼 수 있는 **뷰어**.
2. 펀팩트: 정치인이 **무엇을 많이 먹는지** (식당 랭킹 + 음식종류 추정).
3. **당 / 나이 / 성별 / 띠 / 재산 / 아파트 평수**별 구분.
4. **자기 지역구에서만 먹는 의원** vs **지역구에서 안 먹는 의원**.

## 2. 데이터 원천

- **OhmyNews/KA-money** (`https://github.com/OhmyNews/KA-money`)
  — 오마이뉴스·경향신문·뉴스타파가 선관위 정보공개청구 → OCR·정제한 정치자금 지출내역(2012~2024, 선거자금 제외).
- **라이선스/출처표시 필수**: UI 전역에 `자료: 오마이뉴스·경향신문·뉴스타파 (정치자금 지출보고서)` 노출.
  기존 재산 탭의 오픈와치 출처표시와 동일한 패턴. 원본 PDF/특별페이지 링크 제공.

### 2.1 파일 구조 (검증 완료)

| 구분 | 파일 | 컬럼(위치 기준) | 비고 |
|---|---|---|---|
| 기본(전 연도) | `YYYY_KAPF*.xlsx` `Data` 시트 | 연번, 의원번호, 의원명, 당, 당ID, 지역명, 연월일, 내역, **지출(금액)**, **성명(가맹점)**, **분류** | 헤더 라벨이 연도별 상이(지출/지출금회/지출액, 성명/사용처). 위치로 정규화. |
| 리치(2023~2024만) | `YYYY_KAPF*_수입지출.xlsx` | …+ **주소**, **업종**, 사업자번호, 전화 | 식당행 **주소 96% 존재**, 업종 풍부(음식점/한식/카페…). 지역구·음식종류 분석의 1차 소스. |
| 부가 시트 | `지출내역분류기준`, `의원정보`, `정당코드` | — | 분류 코드 사전. |

### 2.2 음식(식당) 분류 필터

`분류` 값 기준 화이트리스트:
- `간담회_식대` — 외부인사와 식사 (핵심)
- `사무실_식대비` — 보좌진·회식
- `언론_기자식대등` — 기자 간담회 식사
- `간담회_다과` — 커피·다과 (음료/카페)

> 선거비용(`선거비용_*`)은 제외(원천에서도 선거자금 제외). 음/양수 행은 합산해 정정·반환분이 상쇄되도록 한다.

### 2.3 검증된 수치 (22대, 2024 파일)

- 의원 301명(현직 300 + 사퇴/교체 1) — `members.json`과 **이름+당** 매칭 깔끔.
- 식당행 9,329건. 가맹점명은 실제 상호(달구지·일미·한류관·투썸플레이스…).
- 주소로 시·도+구 파싱 가능(대부분 여의도 영등포구 주변).

## 3. 데이터 범위 결정 (승인됨)

- **기간**: 전체 연도 2012~2024 (사용자 선택). 식당 뷰어/랭킹/총액은 전 연도·전 인물 대상.
- **음식종류 표현**: 식당 랭킹 + **음식종류 추정**(업종 우선, 없으면 가게명 휴리스틱; "추정" 라벨 명시).

### 3.1 핵심 제약 (스펙에 명시, UI에 분모 표기)

1. **인구통계 스코프 불일치**: 지출은 전 연도(과거 의원 포함)지만,
   나이·성별·띠·재산·평수 데이터는 **현직 22대 300명**만 존재.
   → 당/나이/성별/띠/재산/평수 **펀팩트 분석은 "현직 의원과 이름 매칭된 부분집합"** 기준.
   식당 뷰어·전체 랭킹은 전원 대상. 각 카드에 "기준: 현직 의원 N명" 등 분모를 표기.
2. **주소·업종 커버리지**: 리치 파일은 2023~2024만 존재 → **지역구 분석·업종 기반 음식종류는 사실상 22대 시기** 데이터.
   주소 OCR은 정제 수준이 낮을 수 있어 시·군·구 파싱은 best-effort, 커버리지 %를 표기.
   **비례대표(무지역구)** 는 "지역구에서 안 먹는 사람"이 아니라 별도 버킷.

## 4. 아키텍처 (기존 `gen-* → server/assets/*.json → /api/* → UI` 패턴)

```
KA-money *.xlsx ──(scripts/gen-dining.mjs, 수동 실행)──▶ server/assets/dining.json (집계·커밋)
                                                              │
                          /api/dining.get.ts (KV 캐시) ◀──────┘
                                                              │
        ┌─────────────────────────────────────────────────────┼──────────────────────────┐
        ▼                                                       ▼                          ▼
  /dining 페이지(뷰어)                              펀팩트 새 탭 "식당"(분석)        members/[id] 식당 카드
```

### 4.1 베이크 스크립트 `scripts/gen-dining.mjs`

- **xlsx 파싱**: 빌드 전용 의존성 `xlsx`(SheetJS, 핀 고정) 추가. read-only.
- **입력 경로**: `KA_MONEY_DIR` 환경변수(기본 `./.cache/ka-money`)에서 로컬 xlsx 읽기.
  최초 1회 개발자가 KA-money 리포를 받아 둔다(대용량 ~150MB → 리포에 커밋하지 않음, `.gitignore`).
- **gen:data 비포함**: CI/배포 빌드에서 150MB를 매번 다루지 않도록 **`gen:dining`는 별도 수동 스크립트**.
  배포는 커밋된 `dining.json`을 사용(= 진실의 원천). 갱신 시 개발자가 `pnpm gen:dining` 후 커밋.
  (재산 시트는 경량 CSV라 gen:data에 포함됐지만, xlsx 18개는 비포함이 합리적 — 사유 명시.)
- **처리 단계**:
  1. 연도별 파일 로드 → 헤더 위치로 컬럼 정규화(지출/성명/분류/주소/업종/지역명).
  2. 식당 분류 화이트리스트 필터, 음수행 합산 상쇄.
  3. 가맹점명 정규화(괄호 보조설명·지점 표기 정리, 동일 상호 묶기).
  4. 업종 + 가게명으로 **음식종류 추정**(한식/중식/일식/양식/고기/분식/카페·음료/주점/구내식당/기타).
  5. 의원 매칭: 지출의 의원명 → `members.json`(이름+당). 매칭 실패분은 `matched:false`로 보존.
  6. 주소 파싱: 시·도 + 시·군·구 추출(`gen-wealth.mjs`의 SIDO/별칭 로직 재사용).
  7. 집계 후 `dining.json` 출력.

### 4.3 API `server/api/dining.get.ts`

- 기존 `wealth.get.ts`처럼 베이크 JSON 서빙. 무거운 분석 탭은 지연 로드(insights 패턴).

### 4.4 타입 `shared/types.ts`

- `DiningData`, `DiningRestaurant`, `DiningMember`, `DiningBreakdownRow`, `DiningDistrict` 추가.

### 4.5 UI

1. **`app/pages/dining/index.vue`** (새 nav `정치자금 맛집` / 아이콘 `Utensils`):
   - 식당 랭킹 테이블(검색·음식종류 필터·방문수/금액 정렬).
   - 의원 dining 프로필 카드(상위 식당, 음식종류 mix, 용도 mix, 지역구 비율).
   - 출처표시 footer.
2. **`app/pages/insights.vue`** 새 탭 `식당`(`tab=dining`, 지연 로드):
   - "무엇을 많이 먹나"(식당·음식종류 랭킹), RankingCard 재사용.
   - 당/나이/성별/띠/재산/평수 분석(기존 Graph* 컴포넌트 스타일의 막대/표).
   - "지역구에서만 먹는 의원" / "지역구에서 안 먹는 의원" 리스트(분모·커버리지 표기).
3. **`app/pages/members/[id].vue`**: 해당 의원 식당 미니 카드(있을 때) + `/dining` 링크.
4. **nav.ts** 항목 추가, **CommandPalette** 등록, **sitemap** 반영.

## 5. 테스트

- `gen-dining.mjs` 순수 유틸 단위테스트(vitest): 컬럼 정규화, 음수 상쇄, 가게명 정규화, 음식종류 추정,
  주소→시군구 파싱, 지역구 매칭. 소형 픽스처 사용.
- 산출 `dining.json` 스키마/불변식 검증(합계 ≥ 0, 분모 일치).
- 로컬 검증: `local-verify-flow` 메모리대로 node-server 빌드+프리렌더 grep(dev SSR 불가).

## 6. 비목표(YAGNI)

- 메뉴·음식명 단위 분석(데이터에 없음).
- 실시간/증분 갱신(연 1회 수동 베이크로 충분).
- 지출 전 분류(교통·사무실 등) 분석 — 이번 범위는 "식당"만.

## 7. 작업 단계(요약)

1. 데이터 파이프라인: `gen-dining.mjs` + 유틸 + 테스트 → `dining.json`.
2. API + 타입.
3. 뷰어 페이지 `/dining` + nav/팔레트/sitemap.
4. 펀팩트 `식당` 탭(분석·지역구).
5. 의원 상세 식당 카드.
6. 로컬 빌드 검증 + 출처표시·분모 점검.
